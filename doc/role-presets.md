# 默认小说智能体

这七个默认角色来自用户提供的小说技能。插件装配的是可编辑的角色提示词，源技能文件保持原样。预设不安装技能依赖、不执行技能脚本，也不自动派遣其他 CLI。

| 默认名称       | 来源技能                                 | 保留的职责与边界                                                                                                             |
| -------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 商业审稿人     | `novel-audit-commercial-review/SKILL.md` | 章首承接、承诺兑现、节拍推进、章末下一点击力四信号；九维评分只作兼容展示；有证据才报问题，只报告不改稿。                     |
| 逻辑审校员     | `novel-audit-logic-check/SKILL.md`       | 认知、状态资源、因果、时空、规则关系和 POV 六族；先核对叙事许可，再判断矛盾；保留候选证据卡、问题 ID、最低成本修复建议。     |
| 文风审校员     | `novel-audit-style-review/SKILL.md`      | 小说 lint → 候选片段 → 语境裁决；用作品风格与前章先例判断，保留误报放行规则，不套用非虚构指标，不自动改稿。                  |
| 正文修订师     | `novel-revise/SKILL.md`                  | 只执行作者授权的问题；保留 A/B/C/D 修改边界、任务地图、不可覆盖快照、差异清单和定向回归，不自动关账。                        |
| 剧情节点设计师 | `novel-start-plot-node/SKILL.md`         | 先给一页状态契约，确认后按需展开十三项设计；明确真实选择、代价、状态变化和下一节点接口，始终保持提案态。                     |
| 剧情结构规划师 | `novel-start-plot-split/SKILL.md`        | 第一轮只给单元契约和紧凑节点链；确认后只展开当前一至两个节点，按因果和状态变化拆分，不按固定章数机械切割。                   |
| 小说主笔       | `novel-write/SKILL.md`                   | 依据已确认设计和最小场景资料写草稿；默认一块、最多连续两块；核对状态、认知、格式与授权，不覆盖待审、修订、锁定或已发布正文。 |

## 为可复用角色做的调整

- 来源技能的角色职责、必要步骤、证据要求、授权边界和输出信息被整理为独立提示词。名称与简介用于设置卡片；完整提示词用于选中的 worker。
- 读取范围改为当前任务指定的项目；不写入原小说目录、个人绝对路径、账号或凭据。原书特有规则只在当前项目已登记采用时适用。
- Evidence Packet、Writer Packet、Issue Manifest、Renwei lint、RAG、快照及 diff 工具都是条件依赖。当前项目真实具备时可复用；不存在时说明资料或工具缺口，不假装已经安装、扫描或验证。
- 保留 `shadow_pending` 迁移边界：若当前项目使用这一闸门，证据包只作定位或影子辅助，不能成为新的正典或扩大授权。
- 去掉固定模型、强度、CLI 路径、后端调度命令及技能自己的工具白名单。CLI Worker 的实际选型、权限和生命周期仍由插件与宿主管理。小说主笔直接承担当前 worker 的写作职责，不再次调用来源技能的外部写手后端。
- 审稿角色可以提出独立复核需要，但不因选中预设就自动派遣孙智能体。没有真实独立复核时说明为单人检查，不能伪造“读者实测”或“对抗审查”。
- 策划确认、正文修订授权、草稿状态限制保留。它们属于用户提供的创作流程，不是插件对所有任务新增的通用审批规则。当前作者已经明确确认的内容直接沿用，不重复询问。

## 使用与维护

在派遣时的“智能体预设”问题中选择角色，或通过“其他”输入临时提示词。在设置的智能体预设页面可调整名称、概述和完整提示词，也可新增或删除预设。临时提示词只用于该 worker，不自动加入预设库。

初次建立预设库时装配七个默认项；后续编辑和删除会保留，不因重启重新覆盖。每个 worker 保存创建时的角色快照，修改预设库只影响之后创建的 worker。审稿、策划和修订角色的名称与 worker 的可重命名调用名称是不同概念。

原始技能还引用共享规范和脚本；本次没有将其复制进插件。提示词本身不能保证模型严格遵循流程，也不能证明小说产出质量。验收应以实际任务范围、文件差异、事件和结果为准。

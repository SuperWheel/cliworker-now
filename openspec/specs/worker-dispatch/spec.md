# worker-dispatch Specification

## Purpose

保证用户在主对话明确指定外部 CLI 时，能够通过插件入口解析名称并进入原生选型与派遣流程；对简称、别名和轻微拼写误差提供可靠处理，同时保持宿主权限、首次选型及直接子 Agent 的边界。

## Requirements

### Requirement: 明确调用与别名路由
插件 SHALL 向主 Agent 提供明确派遣工具及中文调用指引，支持规范名称和常用别名；agy 对应 Antigravity，glm／智谱对应 ZCode。名称解析 SHALL 返回规范 CLI 与解析依据，不得改用其他 CLI 或 shell 执行。

#### Scenario: 用户指定 agy
- **WHEN** 用户要求“调用 agy cli 帮我检查代码”
- **THEN** 提示与工具接受该名称并解析为 antigravity，进入插件选型与派遣路径

#### Scenario: 用户指定 glm
- **WHEN** 用户要求“调用 glm cli”并通过插件提交 glm 名称
- **THEN** 解析结果是 zcode，展示 ZCode 模型，不将 GLM 当作已授权模型

### Requirement: 保守模糊路由与明确意图
插件 SHALL 仅在明确调用上下文解析名称；轻微拼写误差只有唯一可信候选时才可解析。歧义、未知名称和多个目标 MUST 在启动前返回候选或要求澄清。普通模型或 CLI 讨论 MUST 不作为自动派遣授权。

#### Scenario: 唯一名称误差
- **WHEN** 明确调用中传入一个与已知较长名称仅差一个字符且具有唯一候选的名称
- **THEN** 返回规范 CLI 和模糊匹配依据

#### Scenario: 歧义与未知名称
- **WHEN** 请求不能唯一确定 CLI 或传入未知名称
- **THEN** 不启动进程、不保存选型，返回澄清信息

#### Scenario: 普通讨论
- **WHEN** 用户仅询问“GLM 模型有哪些”或引用一段调用示例
- **THEN** 插件指引不要求自动派遣，路由提示不将该消息判作执行请求

### Requirement: 选型和宿主权限保持
派遣 SHALL 以项目和 CLI 隔离模型、思考强度和角色的完整设定，并按主对话确认是否沿用。子 Agent、宿主规划或整体只读状态 MUST 拒绝外部执行。未完成选择和取消选择后 MUST 不启动进程，且不得保存部分设定。复用设定 MUST 仍核验当前账号、模型与强度。

#### Scenario: 首次使用与取消
- **WHEN** 用户首次调用一个未保存完整设定的 CLI，随后取消选型
- **THEN** 不产生 Worker 进程，不自动选择模型，不保存半套设定

#### Scenario: 宿主拒绝执行
- **WHEN** 主会话处于规划模式或整体只读状态，或调用来自子 Agent
- **THEN** 返回原有权限拒绝，名称别名不得绕过边界

#### Scenario: 旧版偏好
- **WHEN** 项目只有旧版模型和强度偏好，尚未确认角色
- **THEN** 首次派遣询问完整设定，不从历史任务猜测角色

### Requirement: OMP 与 Pi 独立身份
工具指引、账号、模型和执行入口 SHALL 将 OMP（Oh My Pi）与 Pi Coding Agent 标为独立 CLI；相同模型或共享桥接实现 MUST 不改变用户选择。执行入口 SHALL 校验所选 CLI 身份和所需原生能力，错误入口在登录、发现或派遣前拒绝。

#### Scenario: 相同模型独立派遣
- **WHEN** 用户分别指定 OMP 和 Pi 使用同名模型
- **THEN** 选择、账号、偏好及会话保持对应 CLI 身份，不推断为同一 CLI

#### Scenario: 错误的程序路径
- **WHEN** OMP 设置指向 Pi 或 Pi 设置指向 OMP
- **THEN** 显示身份不匹配并拒绝启动，不静默替换程序

#### Scenario: 原生安装版本
- **WHEN** 当前原生 Pi 安装满足已核验的桥接能力
- **THEN** 发现、登录和执行使用同一安装；不暗中优先另一旧版本的私有安装

### Requirement: 项目设定与主对话确认
首次派遣 SHALL 询问模型、模型支持的思考强度及角色并保存完整设定。相同项目和 CLI 的新主对话 SHALL 先询问是否沿用以前设定；同一主对话后续派遣 SHALL 使用自身已经确认的设定，Host 重启后仍有效。明确选择不使用角色 SHALL 视为完整设定。

#### Scenario: 新对话沿用
- **WHEN** 项目和 CLI 已有有效完整设定，新主对话首次派遣并选择沿用
- **THEN** 只出现一次沿用询问，任务使用既有模型、强度与角色

#### Scenario: 新对话重新选择
- **WHEN** 新主对话选择不沿用
- **THEN** 询问模型、强度及角色，完成后更新该对话和项目设定

#### Scenario: 同一对话继续派遣
- **WHEN** 已确认设定的主对话再次派遣相同 CLI
- **THEN** 不再次提问，其他对话修改项目默认不改变该对话已确认设定

#### Scenario: 项目或 CLI 不同
- **WHEN** 请求切换项目或 CLI
- **THEN** 对应设定独立读取与确认，不跨项目、CLI 或主对话代答

#### Scenario: 账号或模型变化
- **WHEN** 已确认设定的账号来源改变或模型、强度不再有效
- **THEN** 不静默替换账号或模型；可选目录有效时进入完整选型，无可用目录时返回简短错误且不启动

#### Scenario: 设置页更新默认
- **WHEN** 用户在设置页更改项目的模型和强度
- **THEN** 后续新主对话沿用更新后的默认及已确认角色，已有对话与 Worker 的快照保持不变

### Requirement: 仅两类简洁派遣询问
插件派遣 SHALL 仅生成“模型、思考强度、角色选择”和“是否沿用以前设定”两类询问。选型 MUST 只提供实际模型支持的强度；问题卡 SHALL 省略灰色选项描述、项目路径和说明段落。工具指引 SHALL 要求直接进入插件流程，不要求主 Agent 自行提前提问或增加确认。

#### Scenario: 选择问题卡
- **WHEN** 用户进行完整选型
- **THEN** 问题卡仅含必要标题、问题和选项，不显示免费额度、项目路径和额外说明

#### Scenario: 强度随模型
- **WHEN** 用户选择不同模型
- **THEN** 后续强度选项与该模型实际能力一致；唯一强度可直接采用，不生成额外确认

#### Scenario: 沿用问题卡
- **WHEN** 需要确认是否沿用
- **THEN** 展示既有设定和沿用或重新选择两个选项，不新增第三类问题

### Requirement: 询问并发和取消隔离
相同主对话、项目和 CLI 的并发派遣 SHALL 顺序共享已确认结果，不重复询问；不同主对话 SHALL 独立确认。等待者取消 MUST 及时结束且不取消其他调用的询问；询问发起者取消后其他等待者 SHALL 能重新取得选择机会。插件关闭 MUST 清理等待和询问状态。

#### Scenario: 同对话并发
- **WHEN** 同一对话在首次选型未完成时再次触发相同 CLI
- **THEN** 同时仅一套问题，完成后两个请求均使用同一完整设定

#### Scenario: 不同对话并发
- **WHEN** 不同主对话同时触发同一项目和 CLI
- **THEN** 各自完成自己的选型或沿用确认，不共享未确认答案

#### Scenario: 等待或选择取消
- **WHEN** 某等待者或当前问题发起者取消
- **THEN** 对应调用结束，未完成设定不写入，其他调用可以继续，等待状态最终清理

### Requirement: 同次请求的派遣入口指引
插件 SHALL 在主模型第一次处理已准入的明确 CLI 派遣请求时，提供当前 CLI 对应的入口指引，说明 cliworker_start 先收集选型后启动，无需主模型预先询问模型、强度或角色。指引 MUST 与原始人类消息区分来源，并尊重已准入消息、取消、子 Agent 和工具作用域；不得通过隐藏或拦截通用提问工具实现。

#### Scenario: 原生组装顺序
- **WHEN** Harness 先组装 system prompt 再执行 agent/pre-step，用户本次请求“用agy和我说你好”
- **THEN** 本次模型请求已经包含 cli=antigravity 和进入插件选型的指引，不等到下一步才生效

#### Scenario: 无新增派遣或入口不可见
- **WHEN** 已准入消息不包含人类派遣、步骤被拒绝或取消、当前为子 Agent 或派遣工具不可见
- **THEN** 不新增派遣指引，不修改原始消息，不改变通用提问工具的可见性或执行

#### Scenario: 内部选型不变
- **WHEN** 主模型直接调用 cliworker_start，仅提供 CLI、标题和任务
- **THEN** 插件呈现完整选型或沿用以前设定的问题，用户完成必要选型前不启动 Worker，已有宿主权限检查保持有效

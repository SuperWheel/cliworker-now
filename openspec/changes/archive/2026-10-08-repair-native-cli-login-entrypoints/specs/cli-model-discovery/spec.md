# Spec Delta

## ADDED Requirements

### Requirement: Grok 自身账号模型目录
Grok 的可选模型 SHALL 在当前自身账号明确通过官方 Build 访问门禁后，由该账号认证的官方模型目录与当前原生能力精确求交。目录 HTTP 200、登录成功、匿名、内置或缓存 fallback MUST 不独立证明调用权限；门禁拒绝、门禁未知、成功空响应、认证拒绝、网络失败和插件尚未支持 SHALL 保持不同的诊断含义，详细解释不堆叠到设置页。

#### Scenario: 有效账号目录
- **WHEN** 自身 Grok 官方 Build 访问门禁明确允许、模型请求成功，且模型与强度被当前原生 CLI 明确支持
- **THEN** 显示模型及强度交集，不能因曾缺少实现而无条件清空，也不能用匿名静态 fallback 否定原生动态模型能力

#### Scenario: 目录可读但没有调用权限证据
- **WHEN** 账号能读取模型目录，但官方 Build 访问门禁未明确允许
- **THEN** 模型不可选；门禁未知不能被描述为没有订阅，门禁拒绝不能被目录 HTTP 200 覆盖

#### Scenario: 仅原生公共候选
- **WHEN** 原生 ACP 返回候选，但账号目录请求失败或不可用
- **THEN** 模型不可选；不能将该空列表描述成账号没有模型权益的事实

#### Scenario: 账号改变或查询取消
- **WHEN** 账号在查询期间退出、切换，或用户取消查询
- **THEN** 丢弃原结果并结束 HTTP 请求和原生进程，不恢复旧登录或发起生成

#### Scenario: 请求目标与凭据隔离
- **WHEN** 当前凭据不是受支持的自身官方 Build 认证，或响应尝试跳转至另一目标
- **THEN** 不向其他服务发送凭据，不借用通用 API Key 或其他 CLI 账号查询

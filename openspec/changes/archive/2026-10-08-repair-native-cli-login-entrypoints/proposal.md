# Proposal

## Why

0.6.11 实机复现 Kimi 已有原生登录却只显示已配置、登录按钮直接返回；OMP 登录因自身 logs 目录不在写入白名单而退出；Hermes 在进入登录菜单前复用了任务账号拒绝条件。Grok 的空目录来自插件未确认权限后的无条件拒绝，不能解释成账号没有模型。

## What Changes

- Kimi 按当前 provider 引用的原生令牌判断登录；区分未登录、已登录、失效与普通 API 配置。登录操作遵循已安装 CLI 语义，已有账号不自动退出或删除凭据。
- OMP 原生登录只增加其实际需要的独立日志目录权限，不扩大整个账号目录或其他 CLI 的访问。
- Hermes 使用可隔离的自身登录上下文打开原生菜单，避免已有外部自动导入配置使登录入口死锁；原生账号、历史和全局配置保留，登录后发现与执行使用同一自身来源。精确识别原生自身登录 source，不笼统允许所有 manual 前缀。
- 核实 Grok 当前原生登录状态和模型接口；修正可证明的登录分类。无账号模型范围证据时不伪造列表，详细原因只在交付说明解释，设置页保持短句。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `cli-connection-health`: 自身登录状态与实际原生入口一致；原生登录终端在不借用其他 CLI 账号的条件下可操作。
- `cli-model-discovery`: Grok 使用自身 Build 认证目录与原生能力交集，区别权限未知和账号返回空目录。
- `cli-account-isolation`: 自身登录目录的选择与登录、发现、执行一致；外部账号记录不能阻塞独立自身登录入口。

## Impact

主要影响 Host accounts、Kimi 账号读取、Pi/OMP 账号沙箱、Hermes 账号上下文及 Grok 状态投影，必要的 Client 短状态／动作显示和对应测试。公开账号协议保持兼容。不修改 Harness 核心，不代用户完成授权，不发送模型生成，不删除全局账号。按已有授权完成回归、隔离菜单/UI 验收、空闲 Desktop 更新、本地提交与规格归档，不推送。

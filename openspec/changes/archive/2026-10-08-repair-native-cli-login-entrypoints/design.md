# Design

## Context

见 proposal.md。已安装 Kimi 的 login 没有 force 参数；有 token 时会续用并输出已登录，provider list 的 source=oauth 仅表示引用。OMP 当前 setup 是正确入口，但 logs 位于 agent 的同级。Hermes 原生登录/账号池可能自动导入其他工具，登录前执行任务级 guard 又阻止用户建立自身账号。Grok 目录当前在解析候选后无条件拒绝，不具有账号无权益的诊断意义。

## Goals / Non-Goals

**Goals:** 恢复用户可操作的原生登录路径、真实登录状态，并使登录后的账号来源与发现/执行一致。

**Non-Goals:** 不自动退出、提交凭据或做模型生成；不以放开其他 CLI 账号读取解决启动问题；不增加设置页长解释。

## Decisions

- Kimi 新增只读受限状态读取，按 config 的当前 OAuth 引用对应原生 credentials 槽位；缺令牌、撤销墓碑、失效及可续期分别投影。已有账号的按钮打开可操作的原生管理流程并说明由用户显式退出后重登，不构造不存在的 force 参数或偷偷 logout。全部 Kimi 账号动作进入独立空运行目录，以空 Git/MCP 边界阻断项目查找；保留原生 Trust 由用户确认，关闭后安全清理。
- OMP 在原生账号运行时准备并仅允许自身 logs 子目录写入，保持 agent 账号目录及进程清理边界。使用真实 Seatbelt 回归证明同级和外部目录仍被拒绝。
- Hermes 登录上下文与任务执行预检分离。优先采用插件内独立 Hermes 原生账号目录承接登录，不复制外部池条目、不更改原全局设置；配置禁用自动导入，路径限定该 CLI，并让状态/目录/执行选择同一有效自身来源。根据已安装原生 source/provider 契约精确允许自身登录类型，拒绝借用其他工具的登录入口。已有全局自身账号可在原边界内继续使用。
- Grok 对已核实原生 OIDC 当前账号恢复准确登录状态；模型候选与账号权限分开。官方目录成功仅说明可读取元数据；必须另有当前账号通过 Build 访问门禁的明确证据。原生动态模型与强度解析按已核实安装版能力取交集，不能以匿名静态 fallback 代替。用户明确没有订阅，不发起生成试探；只读诊断严格遵循其授权次数和目标。无法确认则保持空列表，聊天区分插件缺口与账号访问门禁结果。
- 测试/菜单验收使用临时账号目录和模拟服务；真实 Desktop 只打开菜单，不选择提供商、提交授权或发消息。

## Risks / Trade-offs

- 原生 CLI 版本差异 → 当前安装 help/source 证据与能力校验，未知版本不猜参数。
- 登录终端触发自动导入 → 私有配置及文件沙箱共同约束，不仅靠菜单说明。
- 新目录优先级导致来源切换 → 用户显式打开登录时建立独立来源选择标记，之后退出不回退到全局旧账号；执行绑定重新核对，不替旧任务换号。
- 同账号正常续期与退出冲突 → 沿用当前来源/版本重检，不恢复旧快照。

## Migration Plan

版本 0.6.12。保持既有账号、会话与偏好；隔离 preview 验收后在无活动任务时备份并更新 Desktop。回退只还原构建，不回滚任何原生凭据。

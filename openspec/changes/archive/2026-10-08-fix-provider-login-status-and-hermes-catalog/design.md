# Design

## Context

现有共享状态已有 authenticated/configured 区分，但四种 CLI 的账号读取长期固定返回 configured。Hermes 独立来源标记和授权写回实际成功，Nous 的扁平 OAuth 结构、目录和账号绑定未接入；当前原生源码为核验依据。

## Goals / Non-Goals

目标是正确投影本 CLI 各服务商认证，并补齐 Nous 自身账号的完整可用模型链路。模型/偏好结构不变；不接入外部账号、不自动刷新、不发起生成、不修改原生凭据。

## Decisions

- 兼容新增 AccountStatus.logins，元素仅含 providerLabel、authMethod 及可选安全 accountLabel。Host 从已合并且受自身隔离校验的原生凭据投影，已知服务商名称/官方路由映射优先；不传递原始 key、URL 路径或任意账号元数据。多个服务商保留各自认证方式。
- Client 的账号行和侧栏标签共用短格式；authenticated 才为绿点，configured 不凭 authMethod 或目录成功升级。API 不显示 accountLabel；旧 Host 无 logins 时保留原显示。维持单行布局。
- Pi/OMP/OpenCode 复用现有当前来源合并与原生字段检查，补齐 API/OAuth 负例及真实服务商显示。账号展示不改变模型权限，也不放宽已有 OpenCode OAuth 执行保护。
- Hermes 以选中 provider 的真实原生存储格式识别 Nous。官方认证模型元数据使用原生运行时同一 agent key，核对未撤销、身份、用途、到期与路由；未付费账号仅开放官方明确可用范围。绑定覆盖运行时字段，目录查询前后核对来源，保持取消/超时/体积限制和不重定向。
- Nous 使用原生支持的进程级最小有效期参数，读、绑定、目录和执行共用解析结果：默认 120 秒，自身 `.env` 可提高门槛，低于原生 invoke JWT 安全窗口的值归一到 120 秒。避免原生默认提前 1800 秒续期把仍有效账号误判不可用，不改原文件、不自动刷新。
- Nous 目录同时排除原生不支持的非聊天模型、显式无 tools 模型、当前冷却模型与无权益付费模型；强度再与原生实际传输词表求交集。能力缓存按来源及请求版本隔离，旧查询失败或取消不能删掉新查询结果。
- 真实只读诊断按实际需要和已授权范围执行，若自动审批要求独立授权则只暂停该请求；模拟和离线验证先完成，不以审批时间代替用户答复。

## Risks / Trade-offs

- 配置声明被误认为认证 → 严格区分可用原生凭据与模板/引用/缺失/失效，字段名或文件存在不能单独升绿。
- 服务商/身份泄漏 → 使用去敏有限字段，拒绝控制字符及凭据形态，不渲染原生原始输出。
- 账号元数据不等于生成成功 → 按原生权限筛选，真实生成未验证单独记录，不用计费调用猜测。
- 当前原生版本变动 → 固定证据、覆盖真实存储结构；未知格式保持短错误而不借用其他提供商实现。

## Migration Plan

先完成类型检查、回归与隔离 preview，核对真实自身账号投影和 Nous 元数据；确认无活动任务后备份构建并更新 Desktop。原账号/历史/偏好前后核对；必要回退只替换插件构建，保留原生数据。按阶段本地提交，不推送。

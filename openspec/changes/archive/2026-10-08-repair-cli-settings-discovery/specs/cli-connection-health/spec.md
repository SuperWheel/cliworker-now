# Spec Delta

## MODIFIED Requirements

### Requirement: 状态一致和证据范围
设置导航、账号摘要与模型目录失败提示 SHALL 使用一致状态含义。只有新鲜的原生认证成功证据可以显示绿点；本地配置、凭据或可续期令牌存在 MUST 保持中性的待验证状态，不能声称已登录或已连接；刷新恢复后 SHALL 更新显示，不修改账号或既有项目偏好。

#### Scenario: 刷新恢复
- **WHEN** 用户修复原生账号配置后刷新
- **THEN** 导航和账号摘要一致更新，并保留原有会话与模型偏好

#### Scenario: 本地账号可读
- **WHEN** 本地账号或 API 配置读取成功但没有远端调用证据
- **THEN** 展示相应账号来源及证据范围，不声称远端验收成功

#### Scenario: 本地凭据不冒充登录
- **WHEN** 六个 CLI 仅发现本地配置或共享 Host 凭据引用而没有当前原生认证成功证据
- **THEN** 显示本地配置及待验证说明，不显示登录成功绿点；Host 引用不能覆盖原生账号状态

## ADDED Requirements

### Requirement: 账号与模型刷新生命周期
设置 SHALL 对所有 CLI 使用一致的加载中、未配置、待验证和失败语义；新账号检查或账号操作后 MUST 使旧模型结果失效并重新核对，过期或跨 CLI 的异步响应不得覆盖当前面板。打开设置和只读查询 MUST 不自动提交登录或模型任务。

#### Scenario: 刷新中和失败
- **WHEN** 用户刷新账号或模型，随后查询失败
- **THEN** 加载期间不继续显示旧成功指示或允许旧模型选择；失败后显示原因和重试入口

#### Scenario: 切换或关闭
- **WHEN** 查询尚未完成时切换 CLI 或关闭设置
- **THEN** 取消对应查询，迟到结果不能写入其他 CLI，既有偏好保持不变

# Design

## Context

问题与范围见 proposal.md。现有三类主规格与 v0.6.8 实现保留：Pi/OMP/OpenCode 两阶段原生候选及账号 GET、进程清理、精确路由和私有存储。当前 `configured` 显示绿色、Host 凭据优先覆盖账号、本地 OAuth 存在即 authenticated，以及 ZCode/Grok/Hermes 静态目录放行造成证据不足。

## Goals / Non-Goals

**Goals:** 独立 CLI 身份、一致加载、可解释的账号证据及模型筛选。

**Non-Goals:** 不通过计费生成试探所有模型，不自动登录、刷新 OAuth 或迁移用户会话，不修改 Harness 核心或全局 skill。

## Decisions

- Client 统一采用中性本地配置状态；仅原生认证成功可绿。账号刷新使目录失效；查询响应核对 CLI，失败禁用旧目录。不用延迟或虚假进度制造加载感。
- 原生账号状态独立读取；显式 Host 凭据兼容执行来源，但不遮盖原生账号、认证错误或登录入口。每个 CLI 使用自己的原生登录流程。
- Pi/OMP 做入口身份和能力核验；原生 Pi 版本经安装源码与离线测试确认再采用，避免把工具名称或共享 JSON-RPC 当身份。主模型工具说明明确禁止互换。
- 保留现有元数据边界；ZCode/Grok/Hermes 候选需有对应账号及 Worker 支持证据。无法确认的提供商隐藏并说明，不能拿配置当权益。复用有界只读元数据查询或原生能力，不发送 prompt。
- 原生模型决定可用强度。保存、派遣和续聊继续重新验证精确路由，失败不换模型。

## Risks / Trade-offs

- 部分 CLI 无可核验账号模型端点 → 显示待验证或空列表，记录限制，保留账号操作。
- 本机原生安装差异 → 检查实际包和 CLI 能力，失败明确报告；不仅靠版本字符串放行。
- 本地配置含秘密 → 安全读取、仅布尔/状态投影、固定错误；测试隔离 HOME，原文件哈希验证。
- UI 刷新并发 → 请求取消和代次校验，避免旧响应覆盖。

## Migration Plan

自动回归、只读原生探针和隔离构建/UI 验收后，确认无活动任务及账号终端，备份 lib 并正式构建更新 Desktop。保持会话、项目偏好和账号文件不变；可回滚旧 lib。只提交本轮文件与文档新增段落，不推送。

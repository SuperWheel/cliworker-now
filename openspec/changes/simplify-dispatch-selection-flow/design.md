# Design

## Context

动机见 proposal。当前项目偏好只有模型和强度，角色在每次 start 后单独询问，且模型选择先落盘。原生 userQuestions 支持静态多题，不支持模型与强度的组内动态联动。

## Goals / Non-Goals

**Goals:** 以完整设定和主对话确认消除重复及遗漏询问，保持公开 Preference 兼容。

**Non-Goals:** 不改 Harness 问题卡组件、认证、模型目录、CLI 执行权限或历史 Worker；不执行模型生成。

## Decisions

- 在私有项目偏好中扩展可选角色快照及账号绑定；角色 null 表示明确无角色，字段缺失表示旧版未完整选择。公开 preference 读取仍只返回原有字段。设置页更改模型与强度保留角色；新对话读取新默认。
- 单独持久化主对话＋项目＋CLI 的完整确认快照。已确认会话不随其他会话修改默认而变化；不用内存 Map 作为唯一依据，避免 Host 重启重复询问。
- 统一选择编排：优先当前会话有效快照；其次询问是否沿用有效项目设定；否则完整选择。所有路径重新校验当前目录与账号绑定，失效进入现有选型或简短错误，不新增问题类型。
- 先询问模型，再在同一组询问其实际强度与角色；唯一强度时只显示角色。这两步共同属于完整选型，省略所有 detail 和选项 description。不同模型的强度不取并集。
- 按主对话＋项目＋CLI 串行选择，每个等待者可取消；发起者退出后等待者重新读取持久化结果。最终校验通过后才同步写入完整默认和对话快照，取消不保存模型或角色的一部分。
- 继续使用 Worker 自身冻结角色及账号绑定处理续聊。工具提示与 Client pending 文案同步新流程，移除要求主 Agent 自行多问的指引。

## Risks / Trade-offs

- [静态问题 API 无法三字段联动] → 使用模型后接强度与角色的原生多题卡，不伪造能力。
- [旧偏好缺角色] → 升级后首次完整选择一次，不猜历史角色。
- [并发与换号] → 会话内可取消串行、会话间独立；选择后及启动前保留账号与模型校验。
- [私有记录损坏或写入失败] → 校验并失败关闭；不使用不完整快照、不启动 Worker。完整设定写入保持现有原子文件和私有权限。

## Migration Plan

先测试兼容存储、选择分支、取消及账号失效，构建独立 preview 并在真实原生问题组件验收。确认 Desktop 无活动任务和账号终端后更新，核对原账号与历史数据。回退插件代码不删除新增私有记录；旧版本公开偏好结构仍可读取。无真实模型生成。

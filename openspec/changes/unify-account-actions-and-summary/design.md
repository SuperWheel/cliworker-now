# Design

## Context

见 proposal.md。现有 Client 已统一渲染退出样式，差别由三个 CLI 缺少原生 logout 动作造成。原生动作通过 Host AccountManager 管理，Kimi 身份读取独立于模型目录。

## Goals / Non-Goals

保持账号来源、模型和偏好协议。此次补齐退出能力及必要账号显示，不迁移或删除用户认证，不扩大跨 CLI 权限，不以模型生成证明登录。

## Decisions

- 复用现有 AccountAction logout、账号终端及互斥/清理流程；按安装的原生能力选择退出命令或原生菜单，不发明 CLI 参数，不直接删除认证文件。真实账号验收只看按钮；退出行为使用明确模拟或临时账号验证。
- Client 对安全投影先过滤再按方式分组：OAuth 存在则只显示对应去重服务商和“账号登录”；完整认证和安全身份留在 title。仅 API 时保留服务商 API 登录；不因摘要省略改变 Host 认证或模型范围。
- Kimi 从当前原生认证读取安全的账号身份。仅使用具有实际原生证据的字段，拒绝原始 token/key 及不安全格式；保留无身份或读取失败的简短状态。远端身份查询如确有必要，先核对原生端点及数据，再按具体凭据和目标授权执行。
- 保留 Kimi 独立的账号标识展示，不用订阅摘要的邮箱省略规则吞掉本次用户明确要求的 Kimi 身份。

## Risks / Trade-offs

- 退出动作范围过大 → 原生精确能力证据和临时来源测试；不使用全目录删除、跨 CLI 回退或真实用户账号退出验收。
- 身份元数据与密钥混淆 → 有界解析、来源绑定及安全投影，不输出原认证文件。
- UI 精简丢失账号信息 → 保留完整安全 title 和 Host 元数据，模型发现仍按全部实际执行来源筛选。

## Migration Plan

类型检查、必要回归和隔离 preview/UI 验收通过后，确认无活动任务，再备份并更新 Desktop；核对原账号、历史与偏好，记录真实验证和未执行边界，本地提交并归档，不推送。回退仅替换插件构建。
